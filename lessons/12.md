# บทที่ 12: สร้าง Skill ของตัวเอง 🌳

**เป้าหมาย:** ผู้เรียนเข้าใจโครงสร้างของ Skill, สร้าง Skill แรกของตัวเองสำเร็จ และใช้งานได้จริงใน Claude Code

> หมายเหตุถึงนมเย็น: บทนี้เป็นบทลงมือทำเยอะ ให้ทำไปด้วยกันทีละขั้นใน Claude Code เลย (ผู้เรียนอยู่ในนั้นอยู่แล้ว) — สร้างของจริง ไม่ใช่แค่อธิบาย

## หัวข้อ 12.1 — ทบทวน: Skill คืออะไร ต่างจาก CLAUDE.md ยังไง

- Skill = "คู่มือทำงานเฉพาะทาง" ที่ Claude หยิบมาอ่าน **เฉพาะตอนที่งานนั้นโผล่มา** เช่น skill ทำใบเสนอราคา จะถูกเรียกเมื่อพูดถึงใบเสนอราคาเท่านั้น
- เทียบให้เห็นภาพ:
  - **Custom Instructions** (บท 7) = นิสัยประจำตัว AI — ติดตัวทุกแชท
  - **CLAUDE.md** (บท 11) = กติกาประจำโฟลเดอร์ — อ่านทุกครั้งในโฟลเดอร์นั้น
  - **Skill** = ท่าไม้ตายเฉพาะกิจ — หยิบมาใช้เมื่อถึงเวลา ไม่รกสมอง AI ตอนทำงานอื่น
- ข้อดีของ Skill: เขียนละเอียดได้มาก (มีหลายไฟล์ประกอบได้), แชร์ให้คนอื่นใช้ได้, ใช้ซ้ำได้ทุกโปรเจกต์
- **Checkpoint:** ถามผู้เรียน — งานประจำของเขาอันไหนเข้าข่าย "ขั้นตอนตายตัว ทำซ้ำบ่อย อธิบายยาว" บ้าง? นั่นแหละคือว่าที่ skill

## หัวข้อ 12.2 — ผ่าโครงสร้าง Skill

- Skill 1 ตัว = โฟลเดอร์ 1 อัน ข้างในมีไฟล์หลักชื่อ `SKILL.md` เสมอ
- โครงของ `SKILL.md`:

```
---
name: quotation-maker
description: สร้างใบเสนอราคา PDF ใช้เมื่อผู้ใช้ขอทำใบเสนอราคา หรือพูดถึงการเสนอราคาให้ลูกค้า
---

(ต่อจากนี้คือขั้นตอนการทำงานละเอียด เขียนเหมือนสอนพนักงานใหม่:
ข้อมูลบริษัท, โครงเอกสาร, วิธีคำนวณ, ข้อห้าม, ตัวอย่างผลงานที่ดี)
```

- 2 ส่วนสำคัญ:
  1. **description** = ตัวชี้ว่า "เมื่อไหร่ควรหยิบ skill นี้" — เขียนดีสกิลจะถูกเรียกเอง เขียนแย่สกิลจะเงียบ (สำคัญสุด!)
  2. **เนื้อหา** = ขั้นตอนทำงาน — หลักเดียวกับ prompt ที่เรียนมาทั้งหมด: ชัด, มีตัวอย่าง, บอกรูปแบบผลลัพธ์
- ที่เก็บ: โฟลเดอร์ `.claude/skills/` ในโปรเจกต์ (ใช้เฉพาะโปรเจกต์นั้น) หรือ `~/.claude/skills/` ในเครื่อง (ใช้ได้ทุกโปรเจกต์) — รายละเอียดอาจเปลี่ยน เช็คเอกสาร Claude Code ประกอบ
- ฝั่งเว็บ claude.ai บางแพ็กเกจก็มีหน้าให้เพิ่ม/เปิดใช้ skill ได้เช่นกัน — skill ที่เขียนดีจึงพกไปใช้ได้หลายที่ ไม่ติดเครื่องมือเดียว (นมเย็นค้นเช็คสถานะล่าสุดก่อนสอน)
- เกร็ด: คอร์สนี้ผู้เรียนเห็น skill มาตลอดโดยไม่รู้ตัว — ฟีเจอร์อย่าง `/loop` หรือ skill สำเร็จรูปต่างๆ ใน Claude Code ก็คือโครงแบบนี้

## หัวข้อ 12.3 — วิธีสร้างที่ง่ายที่สุด: ให้ Claude สร้างให้

- ไม่ต้องเขียนเองจากศูนย์! บอก Claude Code ว่า:

> "ช่วยสร้าง skill ชื่อ [ชื่อ] สำหรับงาน [อธิบายงาน + ขั้นตอนที่เราทำปกติ + ตัวอย่างผลงานที่ดี] เก็บไว้ที่ .claude/skills/"

- หรือใช้เครื่องมือช่วยสร้าง (เช่น skill-creator ถ้ามีติดตั้ง) — Claude จะถามรายละเอียดแล้วประกอบให้
- บทบาทของเรา: เป็นคนให้ "ความรู้เฉพาะทาง" — ขั้นตอนจริง ตัวอย่างจริง ข้อห้ามจริง — AI เก่งเรื่องจัดโครง แต่เนื้องานต้องมาจากเรา
- วัตถุดิบชั้นดีมีอยู่แล้ว: `templates.md` (บท 6) กับ `workflow.md` (บท 9) ของผู้เรียน แปลงเป็น skill ได้แทบจะตรงๆ

## หัวข้อ 12.4 — ใช้งานและทดสอบ Skill

- วิธีเรียกใช้ 2 แบบ:
  1. **เรียกเอง:** พิมพ์ `/ชื่อสกิล` ใน Claude Code
  2. **ให้มันมาเอง:** พูดถึงงานที่ตรงกับ description → Claude หยิบ skill มาใช้อัตโนมัติ
- ทดสอบ 3 ขั้น:
  1. สั่งงานตรงๆ ดูว่า skill ถูกเรียกไหม (ถ้าไม่ → ปรับ description ให้ตรงคำที่เราใช้จริง)
  2. ดูผลงานว่าตามขั้นตอนที่เขียนไว้ไหม (ถ้าไม่ → เนื้อหาไม่ชัดพอ เพิ่มตัวอย่าง)
  3. ลองกับเคสแปลกๆ ดูว่าพังตรงไหน → เติมข้อยกเว้นเข้าไป
- แนวคิดเดิมกลับมาอีกแล้ว: **สร้าง → ทดสอบ → วนแก้** เหมือน prompt ทุกประการ

## 🏋️ แบบฝึกหัดท้ายบท (ชิ้นส่วนโปรเจกต์ #12)

1. เลือกงานเด่นที่สุดจาก `templates.md` หรือ `workflow.md` มา 1 งาน
2. สร้างเป็น skill จริงใน `.claude/skills/` (นมเย็นช่วยทำไปด้วยกันทีละขั้น — ตั้งชื่อ, เขียน description, แปลง template เป็นขั้นตอน)
3. ทดสอบครบ 3 ขั้นตามหัวข้อ 12.4 และวนแก้อย่างน้อย 1 รอบ
4. คัดลอก skill ที่เสร็จแล้วเก็บลง `my-project/my-skill/` เป็นผลงาน

## สรุปท้ายบท

Skill = ท่าไม้ตายเฉพาะกิจที่เรียกใช้ซ้ำได้ / description คือหัวใจ — ชี้ว่าเมื่อไหร่ถูกเรียก / ให้ Claude ช่วยสร้าง เราให้ความรู้เฉพาะทาง / ทดสอบแล้ววนแก้เสมอ / บทต่อไป: บทสุดท้าย! ประกอบทุกอย่างเป็นโปรเจกต์จบ 🎓
