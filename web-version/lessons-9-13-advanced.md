# บทที่ 9: Advanced Prompting 🌳

**เป้าหมาย:** ผู้เรียนใช้เทคนิคขั้นสูง: ให้ AI คิดเป็นขั้นตอน, ตรวจงานตัวเอง, และต่อ prompt เป็นกระบวนการ

## หัวข้อ 9.1 — ให้ AI คิดเป็นขั้นตอน (Step-by-step)

- งานซับซ้อน (คำนวณ, ตัดสินใจ, วางแผน) สั่งเพิ่มว่า: "คิดทีละขั้นตอน อธิบายเหตุผลก่อนสรุป"
- ผล: คำตอบรอบคอบขึ้น และเราเห็นวิธีคิด — จับผิดได้ง่ายกว่าคำตอบห้วนๆ
- ตัวอย่าง: "ร้านควรขึ้นราคาไหม? วิเคราะห์ทีละขั้น: ต้นทุน → คู่แข่ง → ลูกค้า → ความเสี่ยง → แล้วค่อยสรุปคำแนะนำ"
- โน้ต: AI รุ่นใหม่บางตัวมี "โหมดคิดนาน" (extended thinking / reasoning) ในตัว — เปิดใช้เมื่องานยากจริง

## หัวข้อ 9.2 — ให้ AI ตรวจงานตัวเอง (Self-critique)

- เทคนิคทอง 3 จังหวะ: สั่งงาน → "ติงานตัวเองแบบโหดๆ มีจุดอ่อนตรงไหน" → "แก้ตามที่ติ"
- คุณภาพงานกระโดดขึ้นชัดเจน โดยเฉพาะงานเขียนสำคัญ
- อีกท่า: สลับมุมมอง — "ถ้าคุณเป็นลูกค้าอ่านข้อความนี้ จะรู้สึกยังไง ตรงไหนน่ารำคาญ"
- ท่าผสม: ใช้ AI สองตัวตรวจกัน — เอางานจาก ChatGPT ไปให้ Claude ติ (หรือกลับกัน)

## หัวข้อ 9.3 — ต่อ prompt เป็นกระบวนการ (Prompt Chain)

- งานใหญ่อย่าสั่งครั้งเดียว → แตกเป็นขั้น แต่ละขั้นเอาผลจากขั้นก่อนมาใช้ต่อ
- ตัวอย่าง chain ทำรายงานประจำเดือน:
  1. "สรุปข้อมูลดิบนี้เป็นประเด็นสำคัญ" →
  2. "จากประเด็นเหล่านี้ ทำโครงรายงาน" →
  3. "เขียนรายงานเต็มตามโครง" →
  4. "ติแล้วแก้" (จาก 9.2) →
  5. "สรุปย่อ 5 บรรทัดสำหรับส่งไลน์ผู้บริหาร"
- เขียน chain เก็บไว้ = ได้ "สูตรการทำงาน" ที่ทำซ้ำได้ทุกเดือน — นี่คือหัวใจของ workflow ในบทที่ 12

## หัวข้อ 9.4 — เทคนิคจิปาถะระดับสูง

- บังคับถามก่อนทำ: "ก่อนเริ่ม ถ้ามีอะไรไม่ชัดให้ถามฉันก่อน" — ลดการเดาผิด
- ให้เกรดงาน: "ให้คะแนนงานนี้ 1-10 พร้อมเหตุผล และบอกว่าต้องทำยังไงให้ได้ 10"
- จำกัดขอบเขต: "ตอบจากข้อมูลที่ฉันให้เท่านั้น ถ้าไม่มีในข้อมูลให้บอกว่าไม่มี" — ลด hallucination เวลาทำงานกับเอกสาร
- ขอความเห็นต่าง: "เสนอมุมมองที่ขัดแย้งกับฉันมา 2 มุม" — กันตัวเองคิดเข้าข้างตัวเอง

## 🏋️ แบบฝึกหัดท้ายบท (ชิ้นส่วนโปรเจกต์ #9 — สำคัญมาก)

1. ออกแบบ prompt chain สำหรับงานหลักของโปรเจกต์ประจำตัว (3-5 ขั้น) โดยใส่ขั้น self-critique ไว้ด้วยเสมอ
2. ทดลองรันจริงครบทุกขั้น
3. บันทึกลงไฟล์ใหม่ `my-project/workflow.md` — เขียนเป็นขั้นตอนที่ทำตามได้เลย (นี่คือโครงกระดูกของโปรเจกต์จบ!)

## สรุปท้ายบท

คิดทีละขั้น / ติแล้วแก้ / งานใหญ่แตกเป็น chain / workflow.md คือหัวใจของโปรเจกต์จบ / บทต่อไป: Claude Code — AI ที่ลงมือทำงานในเครื่องเราจริงๆ
# บทที่ 10: รู้จัก Claude Code 🌳

**เป้าหมาย:** ผู้เรียนเข้าใจว่า Claude Code คืออะไร ต่างจากแชทยังไง ติดตั้งและใช้งานพื้นฐานได้

> หมายเหตุถึงนมเย็น: ผู้เรียนกำลังเรียนอยู่ "ใน Claude Code" ตอนนี้เลย! ใช้จุดนี้สอนได้: "ที่คุยกับเราอยู่นี่แหละคือ Claude Code" — เป็นตัวอย่างที่จับต้องได้ที่สุด
>
> ⚠️ ก่อนเริ่มบทนี้ เช็คแพ็กเกจผู้เรียนจาก PROGRESS.md: Claude Code ปกติต้องใช้แพ็กเกจเสียเงิน ถ้าผู้เรียนใช้ฟรี (กรณีเรียนผ่านเวอร์ชันเว็บ) ให้บอกตรงๆ อย่างนุ่มนวล แล้วเสนอ 2 ทาง: (1) เรียนบท 10-11 เป็นภาคทฤษฎีให้เห็นภาพ ไว้มี Claude Code เมื่อไหร่ใช้ได้ทันที หรือ (2) ข้ามไปทำโปรเจกต์จบด้วยเครื่องมือฟรี — ให้ผู้เรียนเลือกเอง ห้ามกดดันให้จ่ายเงิน

## หัวข้อ 10.1 — Claude Code คืออะไร ต่างจากแชทยังไง

- แชท (claude.ai): เราคุย → AI ตอบเป็นข้อความ → เรา copy ไปใช้เอง
- Claude Code: AI อยู่ในเครื่องเรา **ลงมือทำเองได้จริง** — อ่านไฟล์, สร้างไฟล์, แก้ไฟล์, รันคำสั่ง, ทำงานหลายขั้นตอนต่อเนื่องจนจบ
- เปรียบเทียบ: แชท = ที่ปรึกษาปลายสาย / Claude Code = ผู้ช่วยที่นั่งอยู่หน้าคอมเราแล้วทำงานให้ดูต่อหน้า
- ชื่อมีคำว่า Code แต่**ไม่ได้มีไว้สำหรับโปรแกรมเมอร์เท่านั้น** — ใช้จัดการไฟล์เอกสาร, สรุปงาน, จัดระเบียบโฟลเดอร์, ทำงานอัตโนมัติได้หมด (คอร์สนี้ที่ผู้เรียนกำลังเรียนก็คือตัวอย่าง!)

## หัวข้อ 10.2 — ติดตั้งและเริ่มใช้

- มีหลายรูปแบบให้เลือก: แอป desktop (Mac/Windows), ใช้ผ่านเว็บ (claude.ai/code), พิมพ์คำสั่งใน terminal, หรือส่วนขยายใน IDE — แนะนำ**แอป desktop** สำหรับคนไม่ใช่สายเทคนิค (รูปแบบที่มีอาจเพิ่ม/เปลี่ยน ให้นมเย็นค้นเช็คล่าสุดก่อนสอน)
- ขั้นตอนหลัก: ติดตั้ง → ล็อกอินบัญชี Claude → เปิดโฟลเดอร์ที่จะทำงาน → พิมพ์สั่งได้เลย
- แนวคิดสำคัญ: Claude Code ทำงาน "ในโฟลเดอร์ที่เราเปิด" — เหมือนจ้างผู้ช่วยมาประจำที่โต๊ะทำงานตัวหนึ่ง
- รายละเอียดการติดตั้งอาจเปลี่ยน — ให้เช็คจาก claude.com/claude-code ประกอบ

## หัวข้อ 10.3 — งานแรกๆ ที่ควรลอง (ไม่ต้องเขียนโค้ดสักบรรทัด)

- "ดูไฟล์ในโฟลเดอร์นี้หน่อย มีอะไรบ้าง"
- "อ่านไฟล์ report.docx แล้วสรุปให้ฟัง"
- "สร้างไฟล์ checklist งานสัปดาห์นี้จากที่ฉันเล่า"
- "เปลี่ยนชื่อไฟล์รูปทั้งหมดในโฟลเดอร์นี้เป็น วันที่_ชื่องาน"
- "รวมไฟล์สรุปประชุม 4 ไฟล์นี้เป็นรายงานเดียว"
- จุดขาย: งานที่ต้องเปิด 10 ไฟล์ทำทีละอัน → สั่งประโยคเดียวจบ

## หัวข้อ 10.4 — ระบบความปลอดภัย (Permissions)

- Claude Code จะ**ขออนุญาตก่อนทำ**สิ่งที่กระทบไฟล์/ระบบ — เราเห็นทุกอย่างที่มันจะทำ กดอนุญาตหรือปฏิเสธได้
- กติกาที่ดีสำหรับมือใหม่: อ่านก่อนกดอนุญาตเสมอ, เริ่มจากโฟลเดอร์ทดลอง (ไม่ใช่โฟลเดอร์งานจริงทั้งก้อน), งานลบไฟล์ให้ระวังเป็นพิเศษ
- แนะนำให้รู้จัก backup: งานสำคัญควรมีสำเนาก่อนให้ AI จัดการ

## 🏋️ แบบฝึกหัดท้ายบท (ชิ้นส่วนโปรเจกต์ #10)

1. ติดตั้ง Claude Code (ถ้ายังไม่มี — มีแล้วข้ามได้เพราะกำลังใช้อยู่!)
2. สร้างโฟลเดอร์ทดลอง ใส่ไฟล์เอกสาร 2-3 ไฟล์ แล้วสั่งให้ Claude Code อ่าน+สรุป+สร้างไฟล์สรุปรวม
3. ลองสั่งงานที่เกี่ยวกับโปรเจกต์ประจำตัว 1 อย่าง เช่น ให้จัดระเบียบ `my-project/` หรือสร้างไฟล์ template เพิ่ม
4. เล่าประสบการณ์ให้นมเย็นฟัง: ชอบ/งง/กลัวตรงไหน

## สรุปท้ายบท

Claude Code = AI ที่ลงมือทำจริงในเครื่องเรา / ไม่ใช่แค่ของโปรแกรมเมอร์ / ขออนุญาตก่อนทำเสมอ อ่านก่อนกด / บทต่อไป: ปลดล็อคของแรง — สอนให้มันทำงานอัตโนมัติแบบฉลาดขึ้น
# บทที่ 11: Claude Code ขั้นสูง + Automation 🌳

**เป้าหมาย:** ผู้เรียนรู้จัก CLAUDE.md, Skills, MCP และแนวคิด automation — เห็นภาพว่าจะสร้าง "ผู้ช่วยเฉพาะทาง" ของตัวเองได้ยังไง

## หัวข้อ 11.1 — CLAUDE.md: สมองประจำโฟลเดอร์

- ไฟล์ชื่อ `CLAUDE.md` ในโฟลเดอร์ = คำสั่งถาวรที่ Claude Code อ่านทุกครั้งที่เริ่มงานในโฟลเดอร์นั้น
- เหมือน Custom Instructions (บทที่ 7) แต่ผูกกับโฟลเดอร์งาน — แต่ละโปรเจกต์มีกติกาของตัวเอง
- ใส่อะไรได้บ้าง: เราเป็นใคร, งานนี้คืออะไร, ชอบให้ทำงานแบบไหน, ห้ามทำอะไร, ไฟล์ไหนสำคัญ
- **ตัวอย่างที่ดีที่สุดอยู่ตรงหน้า:** คอร์สนี้ทั้งคอร์สคือ CLAUDE.md ไฟล์เดียว! เปิดให้ผู้เรียนดูได้เลยว่า "นมเย็น" ถูกสร้างยังไง — แล้วบอกว่า "คุณก็สร้างผู้ช่วยแบบนี้ได้เหมือนกัน"

## หัวข้อ 11.2 — Skills: ท่าไม้ตายสำเร็จรูป

- Skill = ชุดคำสั่ง+ความรู้สำเร็จรูปที่สอน Claude ทำงานเฉพาะทาง เช่น ทำไฟล์ Excel, ทำสไลด์, ทำ PDF
- มี skill สำเร็จรูปให้ใช้ และสร้างเองได้ — บทที่ 12 จะสอนลงมือสร้างจริงแบบละเอียด
- ปัจจุบัน skill ไม่ได้จำกัดอยู่แค่ใน Claude Code — ฝั่งเว็บ claude.ai ก็เริ่มรองรับการใช้/เพิ่ม skill แล้วในบางแพ็กเกจ และมีระบบ plugin ให้ติดตั้งชุดเครื่องมือสำเร็จรูปเพิ่มด้วย (รายละเอียดเปลี่ยนบ่อย ให้นมเย็นค้นเช็คล่าสุดก่อนสอน)
- ตัวอย่างการใช้: "สร้างใบเสนอราคาเป็น PDF", "ทำสไลด์นำเสนอจากรายงานนี้", "สรุปยอดขายเป็นไฟล์ Excel พร้อมกราฟ"
- แนวคิดสำหรับผู้เรียน: งานประจำที่มีขั้นตอนตายตัว → เหมาะทำเป็น skill

## หัวข้อ 11.3 — MCP: ต่อ AI เข้ากับเครื่องมืออื่น

- MCP (Model Context Protocol) = "ปลั๊ก" มาตรฐานที่ให้ Claude ต่อกับบริการอื่น: Google Drive, ปฏิทิน, อีเมล, Notion, ฐานข้อมูล ฯลฯ
- ต่อแล้วได้อะไร: "ดูปฏิทินพรุ่งนี้แล้วสรุปว่าต้องเตรียมอะไร", "หาไฟล์ใน Drive แล้วสรุป", "อ่านงานใน Notion แล้วจัดลำดับความสำคัญ"
- ไม่ต้องเข้าใจเทคนิคลึก — แค่รู้ว่า "ต่อได้" และการต่อทำผ่านหน้า settings/connectors
- เตือนความปลอดภัย: ต่อเฉพาะบริการที่เชื่อถือได้ และเข้าใจว่าให้สิทธิ์อะไรไป

## หัวข้อ 11.4 — คิดแบบ Automation

- สูตรมองหางานที่ควร automate: ทำซ้ำบ่อย + ขั้นตอนชัด + ใช้เวลานาน = เป้าหมายชั้นดี
- ตัวอย่าง workflow อัตโนมัติที่คนทั่วไปทำได้:
  - เช้าวันจันทร์: "อ่านไฟล์ยอดขายสัปดาห์ก่อน → สรุป → ร่างอีเมลรายงานหัวหน้า"
  - หลังประชุม: "เอาโน้ตดิบ → ทำสรุปประชุม → แยก action items → สร้างไฟล์ติดตามงาน"
  - งานเอกสารซ้ำๆ: "อ่านข้อมูลลูกค้าใหม่ → กรอกลง template ใบเสนอราคา → สร้าง PDF"
- หลักคิดสำคัญ: automation ที่ดีเริ่มจาก workflow ที่เราทำเองจนเชี่ยวก่อน (บทที่ 9) แล้วค่อยส่งมอบให้ AI

## 🏋️ แบบฝึกหัดท้ายบท (ชิ้นส่วนโปรเจกต์ #11 — ใกล้เส้นชัย!)

1. เขียน `CLAUDE.md` ฉบับแรกของตัวเอง สำหรับโฟลเดอร์งานจริง 1 โฟลเดอร์ (นมเย็นช่วยร่าง โดยอิงจาก Custom Instructions บทที่ 7 + workflow บทที่ 9)
2. ทดสอบ: เปิด Claude Code ในโฟลเดอร์นั้น สั่งงาน แล้วดูว่ามันทำตามกติกาใน CLAUDE.md ไหม
3. บันทึกไฟล์ CLAUDE.md ที่เขียนลง `my-project/my-claude-md.md` เก็บเป็นผลงาน

## สรุปท้ายบท

CLAUDE.md = ผู้ช่วยประจำโฟลเดอร์ / Skills = ท่าสำเร็จรูป / MCP = ต่อกับโลกภายนอก / automation เริ่มจาก workflow ที่เราเชี่ยว / บทต่อไป: ลงมือสร้าง Skill ของตัวเองจริงๆ!

## หัวข้อ 12.1 — ทบทวน: Skill คืออะไร ต่างจาก CLAUDE.md ยังไง

- Skill = "คู่มือทำงานเฉพาะทาง" ที่ Claude หยิบมาอ่าน **เฉพาะตอนที่งานนั้นโผล่มา** เช่น skill ทำใบเสนอราคา จะถูกเรียกเมื่อพูดถึงใบเสนอราคาเท่านั้น
- เทียบให้เห็นภาพ:
  - **Custom Instructions** (บท 7) = นิสัยประจำตัว AI — ติดตัวทุกแชท
  - **CLAUDE.md** (บท 11) = กติกาประจำโฟลเดอร์ — อ่านทุกครั้งในโฟลเดอร์นั้น
  - **Skill** = ท่าไม้ตายเฉพาะกิจ — หยิบมาใช้เมื่อถึงเวลา ไม่รกสมอง AI ตอนทำงานอื่น
- ข้อดีของ Skill: เขียนละเอียดได้มาก (มีหลายไฟล์ประกอบได้), แชร์ให้คนอื่นใช้ได้, ใช้ซ้ำได้ทุกโปรเจกต์
- **Checkpoint:** ถามผู้เรียน — งานประจำของเขาอันไหนเข้าข่าย "ขั้นตอนตายตัว ทำซ้ำบ่อย อธิบายยาว" บ้าง? นั่นแหละคือว่าที่ skill

## หัวข้อ 12.2 — ผ่าโครงสร้าง Skill

- Skill 1 ตัว = โฟลเดอร์ 1 อัน ข้างในมีไฟล์หลักชื่อ `SKILL.md` เสมอ
- โครงของ `SKILL.md`:

```
---
name: quotation-maker
description: สร้างใบเสนอราคา PDF ใช้เมื่อผู้ใช้ขอทำใบเสนอราคา หรือพูดถึงการเสนอราคาให้ลูกค้า
---

(ต่อจากนี้คือขั้นตอนการทำงานละเอียด เขียนเหมือนสอนพนักงานใหม่:
ข้อมูลบริษัท, โครงเอกสาร, วิธีคำนวณ, ข้อห้าม, ตัวอย่างผลงานที่ดี)
```

- 2 ส่วนสำคัญ:
  1. **description** = ตัวชี้ว่า "เมื่อไหร่ควรหยิบ skill นี้" — เขียนดีสกิลจะถูกเรียกเอง เขียนแย่สกิลจะเงียบ (สำคัญสุด!)
  2. **เนื้อหา** = ขั้นตอนทำงาน — หลักเดียวกับ prompt ที่เรียนมาทั้งหมด: ชัด, มีตัวอย่าง, บอกรูปแบบผลลัพธ์
- ที่เก็บ: โฟลเดอร์ `.claude/skills/` ในโปรเจกต์ (ใช้เฉพาะโปรเจกต์นั้น) หรือ `~/.claude/skills/` ในเครื่อง (ใช้ได้ทุกโปรเจกต์) — รายละเอียดอาจเปลี่ยน เช็คเอกสาร Claude Code ประกอบ
- ฝั่งเว็บ claude.ai บางแพ็กเกจก็มีหน้าให้เพิ่ม/เปิดใช้ skill ได้เช่นกัน — skill ที่เขียนดีจึงพกไปใช้ได้หลายที่ ไม่ติดเครื่องมือเดียว (นมเย็นค้นเช็คสถานะล่าสุดก่อนสอน)
- เกร็ด: คอร์สนี้ผู้เรียนเห็น skill มาตลอดโดยไม่รู้ตัว — ฟีเจอร์อย่าง `/loop` หรือ skill สำเร็จรูปต่างๆ ใน Claude Code ก็คือโครงแบบนี้

## หัวข้อ 12.3 — วิธีสร้างที่ง่ายที่สุด: ให้ Claude สร้างให้

- ไม่ต้องเขียนเองจากศูนย์! บอก Claude Code ว่า:

> "ช่วยสร้าง skill ชื่อ [ชื่อ] สำหรับงาน [อธิบายงาน + ขั้นตอนที่เราทำปกติ + ตัวอย่างผลงานที่ดี] เก็บไว้ที่ .claude/skills/"

- หรือใช้เครื่องมือช่วยสร้าง (เช่น skill-creator ถ้ามีติดตั้ง) — Claude จะถามรายละเอียดแล้วประกอบให้
- บทบาทของเรา: เป็นคนให้ "ความรู้เฉพาะทาง" — ขั้นตอนจริง ตัวอย่างจริง ข้อห้ามจริง — AI เก่งเรื่องจัดโครง แต่เนื้องานต้องมาจากเรา
- วัตถุดิบชั้นดีมีอยู่แล้ว: `templates.md` (บท 6) กับ `workflow.md` (บท 9) ของผู้เรียน แปลงเป็น skill ได้แทบจะตรงๆ

## หัวข้อ 12.4 — ใช้งานและทดสอบ Skill

- วิธีเรียกใช้ 2 แบบ:
  1. **เรียกเอง:** พิมพ์ `/ชื่อสกิล` ใน Claude Code
  2. **ให้มันมาเอง:** พูดถึงงานที่ตรงกับ description → Claude หยิบ skill มาใช้อัตโนมัติ
- ทดสอบ 3 ขั้น:
  1. สั่งงานตรงๆ ดูว่า skill ถูกเรียกไหม (ถ้าไม่ → ปรับ description ให้ตรงคำที่เราใช้จริง)
  2. ดูผลงานว่าตามขั้นตอนที่เขียนไว้ไหม (ถ้าไม่ → เนื้อหาไม่ชัดพอ เพิ่มตัวอย่าง)
  3. ลองกับเคสแปลกๆ ดูว่าพังตรงไหน → เติมข้อยกเว้นเข้าไป
- แนวคิดเดิมกลับมาอีกแล้ว: **สร้าง → ทดสอบ → วนแก้** เหมือน prompt ทุกประการ

## 🏋️ แบบฝึกหัดท้ายบท (ชิ้นส่วนโปรเจกต์ #12)

1. เลือกงานเด่นที่สุดจาก `templates.md` หรือ `workflow.md` มา 1 งาน
2. สร้างเป็น skill จริงใน `.claude/skills/` (นมเย็นช่วยทำไปด้วยกันทีละขั้น — ตั้งชื่อ, เขียน description, แปลง template เป็นขั้นตอน)
3. ทดสอบครบ 3 ขั้นตามหัวข้อ 12.4 และวนแก้อย่างน้อย 1 รอบ
4. คัดลอก skill ที่เสร็จแล้วเก็บลง `my-project/my-skill/` เป็นผลงาน

## ขั้นที่ 2 — ประกอบเป็นโปรเจกต์สมบูรณ์

ให้ผู้เรียนสร้างไฟล์สุดท้าย `my-project/README.md` — "คู่มือใช้งานโปรเจกต์ของฉัน" ประกอบด้วย:

1. **ชื่อโปรเจกต์ + มันแก้ปัญหาอะไร** (2-3 ประโยค)
2. **วิธีใช้งานทีละขั้น** — ตั้งแต่เปิดเครื่องมือ จนได้ผลลัพธ์ (อ้างอิง prompt/template/workflow/skill ที่มี)
3. **เครื่องมือที่ใช้** — แชทตัวไหน, Project ไหน, Claude Code + skill ตรงไหน
4. **เวลาที่ประหยัดได้** — ประเมินคร่าวๆ เทียบก่อน/หลังใช้ AI

เคล็ดลับ: ให้ผู้เรียนลองใช้ AI ช่วยเขียน README นี้เอง — นี่แหละคือข้อสอบปลายภาคตัวจริง (เขาต้องสั่ง AI เป็นแล้ว!)

## ขั้นที่ 4 — นมเย็นรีวิว

รีวิวอย่างจริงใจและสร้างสรรค์ ตามเกณฑ์:

- ✅ ใช้งานได้จริงไหม — คนอื่นอ่าน README แล้วทำตามได้หรือเปล่า
- ✅ prompt มีครบองค์ประกอบไหม (สูตรบท 3+5)
- ✅ มีจุดตรวจสอบความถูกต้องไหม (บท 2: hallucination, บท 8: ตัวเลข)
- ✅ skill ถูกเรียกใช้ได้จริงไหม (บท 12)
- ✅ ประหยัดเวลาจริงไหม
- 💡 เสนอ 2-3 ไอเดียต่อยอด
